# Codex rules

- Deterministic core нельзя заменять LLM.
- AI может быть только auxiliary / interpretation layer.
- Не менять production logic без тестов.
- Не делать big-bang refactoring.
- Сначала читать AGENTS.md, README.md, SYSTEM_MAP.md и остальные обязательные документы из AGENTS.md.
- Если задача неоднозначная — сначала proposal, потом implementation.
- Не создавать новые архитектурные сущности без явной причины.

## Git and delivery

- По умолчанию работать непосредственно в `main`, если среда это позволяет.
- Не создавать feature branches или worktrees, если пользователь явно не просит
  этого и среда не требует изолированного checkout. Не создавать PR без явного
  указания пользователя.
- До изменений проверить ветку, рабочее дерево и состояние относительно
  `origin/main`. Сохранить существующие незакоммиченные изменения; не включать
  чужие изменения в свой commit и не считать любой checkout безопасным для push.
- Перед commit выполнить релевантные тесты или проверки документации. Делать
  небольшие логически цельные commits со ссылкой на issue, например:
  `feat(recovery): support manual physiology observations (#158)`.
- Выполнять push завершённых изменений в `origin/main`, когда это запрошено.
  Не применять force-push, не переписывать опубликованную историю и не обходить
  защиты репозитория. Отклонённый push требует проверки причины, а не обхода.
- Следовать [правилам Git и необязательных PR](PR_WORKFLOW_RULES.md), включая
  ограничения cloud-среды и условия завершения issue.
- Не выполнять ручной production deploy, когда доступен централизованный CI/CD.
  Переходный ручной путь требует явного разрешения и успешного CI точного SHA.
- Не включать автоматический production deploy или автоматическое закрытие issue,
  пока необходимые компоненты не реализованы, протестированы и явно одобрены
  для активации. Текущая готовность описана в
  [production delivery](../../architecture/PRODUCTION_DELIVERY.md).
